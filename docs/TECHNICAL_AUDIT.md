# Sanchay AI — Technical Audit & Vulnerability Matrix

This document provides a comprehensive technical audit of the **Sanchay AI** codebase prior to the production hardening refactor, cataloging identified design flaws, data leakage risks, inference inconsistencies, and architectural gaps alongside their remediation plans and verification statuses.

---

## 1. Executive Summary & Architecture Overview

| Area | Current Implementation Status | Identified Risks |
| :--- | :--- | :--- |
| **ML Feature Engine** | Split between `ml/features.py` (relational batch) and `ml/inference.py` (online dict extraction) | Severe training/inference feature divergence; hardcoded default approximations during inference (e.g. `payment_count=3.0`, `days_between_payments=45.0`); random noise injected in training features. |
| **Synthetic Validation** | Single generator (Generator A) generates both features and deterministic fraud labels | Label leakage through feature correlation; model learns generator's rule heuristics rather than generalized risk; claims ~98% ROC-AUC on synthetic data without independent validation. |
| **Cross-Validation** | Claims 5-fold CV in documentation; actually runs single train/val split with 3-fold calibration | Documentation mismatch; lack of true out-of-fold (OOF) cross-validation and entity/group holdouts. |
| **Temporal & Entity Leakage** | Random split across all projects without respecting time or contractor/district clusters | Future features (e.g., final expenditure, post-hoc audit flags) accessible at sanction time; contractor records split across train/test leaking entity behavior. |
| **Risk Fusion & Terminology** | Hardcoded arbitrary weights (`0.35 ML + 0.25 Rules + 0.20 Anomaly + 0.10 Contractor + 0.10 Docs`); UI claims "Fraud Detected" | Unjustified heuristic weights; overclaiming deterministic criminal fraud from probabilistic anomaly models. |
| **RAG & API Latency** | Claims `0.06 ms` RAG latency and `18.4 ms` E2E API latency | In-memory micro-benchmark claimed as end-to-end latency; ignores real embedding/vector retrieval/LLM overheads. |
| **Security & Diagnostics** | Public `/docs` enabled by default; `/health` leaks raw database exception strings | Information leakage in health checks; lack of environment-aware Swagger protection. |

## 2. Comprehensive Issue Register

| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **P0-01** | **Training / Inference Feature Divergence & Hardcoded Baselines** | **P0 (Critical)** | `ml/inference.py` uses `DEFAULT_BASELINES` hardcoding `payment_count=3.0`, `days_between_payments=45.0`, `peer_cost_deviation_zscore=0.1`, etc. `ml/features.py` computes random noise `expenditure * uniform(0.95, 1.05)`. | Online inference evaluates hardcoded fake defaults instead of actual project telemetry. Model predictions do not reflect real project data. | Build a single canonical `FeatureBuilder` in `ml/features/` shared identically across training, batch evaluation, and online API inference. Calculate actual payment and velocity metrics from telemetry; return explicit missing indicators when unprovided. | `ml/features/`, `ml/features.py`, `ml/inference.py`, `backend/ml/` | `test_data_contract.py` (Assert training features == inference features for identical input) | **Resolved** |
| **P0-02** | **Synthetic Generator Overfitting & Target Leakage** | **P0 (Critical)** | `data/generate.py` creates fraud labels using specific rule thresholds (e.g., `gap > 25%`) and trains models on the exact same dataset. | High performance (PR-AUC 0.93+) reflects learning the generator's rule script, not robust anomaly detection. | Create an independent **Generator B** (`data/generate_ood.py`) with orthogonal fraud patterns (contractor collusion rings, documentation masking, unusual payment sequencing, district drift) for untouched external holdout validation. | `data/generate.py`, `data/generate_ood.py`, `ml/train.py`, `ml/evaluate.py` | `test_ood_evaluation.py` | **Resolved** |
| **P0-03** | **Temporal & Entity Data Leakage** | **P0 (Critical)** | Features like completion delay and final expenditure are computed without respect to prediction timestamp; random train/test split leaks contractor and district IDs. | Model uses future post-completion information to predict sanction-time risk; contractor memorization inflates test performance. | Introduce `prediction_timestamp` point-in-time feature filtering (`AVAILABLE_AT_SANCTION`, `AVAILABLE_DURING_EXECUTION`, etc.); implement GroupKFold / StratifiedGroupKFold on `contractor_id` and temporal splits. | `ml/features/temporal.py`, `ml/features/builder.py`, `docs/FEATURE_AVAILABILITY.md` | `test_temporal_leakage.py`, `test_group_leakage.py` | **Resolved** |
| **P0-04** | **Missing 5-Fold Cross-Validation Implementation** | **P0 (Critical)** | `ml/train.py` trained on static train/val split while claiming 5-fold CV in README. | Scientific claim mismatch; benchmark is susceptible to split variance. | Implement true 5-fold Stratified / StratifiedGroup cross-validation generating out-of-fold (OOF) predictions for model selection. | `ml/train.py`, `ml/evaluate.py` | `test_cross_validation.py` | **Resolved** |
| **P1-01** | **Uncalibrated Probability & Overclaiming "Fraud"** | **P1 (High)** | Raw model probabilities presented as "Confidence 94%" or "Fraud Detected".
